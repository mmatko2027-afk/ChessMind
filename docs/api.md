# API ChessMind

## 1. Загальна інформація

API забезпечує обмін даними між користувацьким інтерфейсом та серверною частиною ChessMind.

Для обміну використовується HTTP із форматом JSON.

## 2. Основні маршрути

| Метод | Маршрут | Призначення |
|---|---|---|
| GET | /health | Перевірка стану сервера |
| POST | /api/games | Створення нової партії |
| GET | /api/games/{game_id} | Отримання стану партії |
| POST | /api/games/{game_id}/moves | Виконання шахового ходу |
| POST | /api/coach/explain | Запит до AI-помічника |
| POST | /api/games/analyze | Запуск аналізу партії |
| GET | /api/games/analyze/{job_id} | Отримання результату аналізу |

## 3. Перевірка стану сервера

GET /health

Приклад відповіді:

{
  "status": "ok",
  "version": "0.1.0",
  "provider": "mock",
  "model": "chessmind-mock",
  "mode": "mock",
  "storage": "ok",
  "extra": {
    "chess_engine": "not_loaded"
  },
  "uptime_s": 12
}

Цей маршрут не викликає мовну модель, а лише перевіряє стан застосунку.

## 4. Створення шахової партії

POST /api/games

Приклад запиту:

{
  "level": "beginner",
  "opponent": "computer",
  "assistant_position": "right",
  "assistant_appearance": "owl",
  "voice_enabled": false
}

Приклад відповіді:

{
  "game_id": "game-001",
  "status": "active",
  "level": "beginner",
  "current_turn": "white"
}

## 5. Виконання шахового ходу

POST /api/games/{game_id}/moves

Приклад запиту:

{
  "move": "e2e4"
}

Приклад відповіді:

{
  "game_id": "game-001",
  "move": "e2e4",
  "status": "active",
  "current_turn": "black",
  "fen": "rnbqkbnr/pppppppp/8/8/4P3/8/PPPP1PPP/RNBQKBNR b KQkq - 0 1"
}

Сервер перевіряє, чи дозволений такий хід правилами шахів. Якщо хід неправильний, він не змінює стан партії.

## 6. Запит до AI-помічника

POST /api/coach/explain

Приклад запиту:

{
  "game_id": "game-001",
  "question": "Чому я не можу походити цією фігурою?",
  "position": "current"
}

Приклад відповіді:

{
  "answer": "Ця фігура не може рухатися на вибране поле за правилами шахів.",
  "suggestion": "Спробуйте вибрати інше поле.",
  "request_id": "req-001"
}

## 7. Аналіз завершеної партії

POST /api/games/analyze

Приклад запиту:

{
  "game_id": "game-001"
}

Відповідь сервера:

{
  "job_id": "analysis-001",
  "status": "pending"
}

Для отримання результату використовується:

GET /api/games/analyze/{job_id}

Приклад відповіді:

{
  "job_id": "analysis-001",
  "status": "completed",
  "result": {
    "summary": "Партію завершено.",
    "mistakes": [],
    "recommendations": []
  }
}

Можливі стани завдання: pending, running, completed, failed.

## 8. Формат помилок

Усі помилки повертаються в єдиному форматі:

{
  "error": {
    "kind": "invalid_move",
    "message": "Неможливо виконати цей шаховий хід.",
    "retryable": false,
    "request_id": "req-002"
  }
}

## 9. HTTP-статуси

| Код | Значення |
|---|---|
| 200 | Запит успішно виконано |
| 202 | Завдання прийнято в обробку |
| 400 | Некоректний запит |
| 404 | Партію або завдання не знайдено |
| 409 | Конфлікт стану партії |
| 422 | Помилка перевірки даних |
| 429 | Забагато запитів |
| 503 | Сервіс тимчасово недоступний |
| 504 | Перевищено час очікування |

## 10. Контракт AI-провайдера

Усі AI-провайдери повинні мати однаковий інтерфейс.

На вхід передаються:
- текст запитання;
- поточна шахова позиція;
- додатковий контекст партії.

На виході повертається структурована відповідь:
- answer — пояснення;
- suggestion — рекомендація;
- request_id — ідентифікатор запиту.

Для початкового прототипу використовується mock-провайдер. Він повертає тестові відповіді без звернення до справжньої мовної моделі.
